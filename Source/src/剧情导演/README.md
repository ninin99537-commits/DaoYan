# 剧情导演 · 剧情编排系统

一个运行在酒馆助手 (Tavern Helper) 中的脚本项目。同族第三块拼图：**彼方管"人"、烟火管"世界"，剧情导演管"戏"**——它不给主 AI 新设定、不记录世界事实，只做剧情的编排：伏笔、冲突、节奏、挫折与反转，让任何世界观（修仙/科幻/现代都市）都能写出电视剧/小说/电影那样的跌宕起伏。

## 为什么需要它

主 AI 有三个**结构性**缺陷，各对应一个机制：

1. **视野缺陷**：只看得见最近几层楼——第 5 楼埋的伏笔，第 40 楼早已出了视野。→ **剧情账本**（外置的长线记忆）。
2. **迎合缺陷**："舔玩家"，除非用户明令否则绝不写失败。→ **导演指令**（外部剧本的既定安排；演员不为剧本里角色的死亡负责）。
3. **结构缺陷**：平铺直叙，没有"压制→爆发→喘息"的波形。→ **导演引擎**（代码层结构规则）。

## 工作原理

每次 AI 完成正文回复后（频率可配，默认每轮）：

```
正文生成完成（防抖 800ms，连发只推最后一条）
      ↓
导演引擎（独立 OpenAI 兼容 API）读「剧情账本 + 最近正文 + 世界书」
      ↓
输出「账本更新 + 上一幕核验 + 下一幕指令」
      ↓
代码层结构规则调整节拍 + 装配本幕指令 → 写入楼层快照
      ↓
双层注入：编剧备忘（世界书常驻条目） + 本幕指令（生成前注入）
```

### 剧情账本（四本账 + 一个读数）

- **章回**（活跃 ≤1）：章号/主题/计划高潮/进度，按剧情事件分章、不以楼层计数。
- **伏笔**（≤8）：`{编号, 内容(冻结), 埋设层, 状态, 回收窗口, 关联冲突}`。状态机 `埋下→潜伏→发酵→已引爆→已消亡`；**编号由脚本签发、全局单调递增永不复用**；**内容写下即冻结**（只改状态，防"玩偶变蛋糕"）。
- **冲突**（≤4）：`{名, 对立面, 赌注, 强度, 阶段, 下一步, 顶回次数}`，阶段 `铺垫→升级→僵持→决战→收束→已收档`。
- **角色弧线**（≤5）：`{角色, 缺口, 阶段, 下一步契机}`，阶段 `…→闭环`。
- **张力读数**：由**代码按节拍增量表折算**（高潮 +4、受挫 +2、余波 −3……），AI 报的 0~10 仅按 30% 权重校正。

### 指标口径（§3 判据 · 别把它算错）

- **伏笔回收率 = `指标.累计了结 / 指标.累计埋设`（队列口径）**：同一批伏笔的比。
  `累计埋设` 在**签发新伏笔**时 +1（单调、不随章节清零）；`累计了结` 在某条伏笔**首次**转入 `已引爆`/`已消亡` 时 +1，**按编号去重**（同一条翻转多次只算一次）。
- **绝不拿 `章节统计.埋设数/回收数` 求和相除** —— 那两栏是"**哪一章**埋下 / **哪一章**了结"，
  第 2 章回收第 1 章埋的伏笔会让分子凭空多、分母不动，于是算出 **111%**（真机踩过）。
  它们只作"本章活动量"看。
- **迁移播种**：老账本没有这两个计数器时，装载时用**现存伏笔**播种（`累计埋设 = 现存条数`、`累计了结 = 现存终态条数`）。
  ⚠️ **只能以现存条目为准**：此前已被容量淘汰（伏笔上限 8）或早已删除的历史项**无法计入**，所以早期账本的分母会偏小。
- 数据异常（`累计了结 > 累计埋设`）**不静默夹断**：标记 `伏笔回收率异常`、日志打印两个原始数字，面板显示 `>100%?` + 原因。
- **`判据.起伏次数`** 由 `章节统计` 聚合（含进行中的那一章），活指标与结算卡都用它 —— 免得"读终值再重算"。
- **`指标.终值`**：剧终那一刻把 `计算判据()` 的结果快照进去（**写一次、只读不重算**），同时打一行成绩单进日志页；
  「清除已剧终」会清空 `终值`（恢复游玩后挂旧成绩会误导），但**日志页那一行留着**，随时可回看。

### 导演引擎（五条代码层结构规则）

1. **张力曲线**：连续 3 幕高张力 → 强制喘息幕；连续 3 幕低张力 → "山雨欲来"（静中埋险）。
2. **契诃夫之枪**：伏笔逾期优先回收；已失去意义的**允许自然消亡，不硬造**。
3. **收束调度**：章回逼近收束 → 未回收伏笔向本章高潮汇聚。
4. **高潮后必有代价**：高潮幕之后强制"战后余波"（**仅档 3/4**）。
5. **执行核验**：核验上一道指令是否被真正执行；未执行则升级下一道指令的强度——**最多连升 2 次、不越当前档位**。

### 导演指令 = 外部授权

注入给主 AI 的不是事实，是**编排**（节拍 + 硬性要求 + 伏笔现场 + 禁止事项）。挫折/死亡由外部剧本既定，主 AI 只是执行，从而绕开迎合倾向。指令头部渲染当前**强度档位**与**红线**；玩家冲突处理**按档缩放**：档 1/2 玩家行动正常生效、指令让位；档 3/4 才允许"戏剧性失败/变形"。

## 用户控制

- **强度滑杆 4 档**：1 轻松日常 / 2 平稳叙事 / **3 跌宕起伏（默认）** / 4 残酷。
- **红线**：钉死不可触碰项（默认无红线，"完全交给剧本"），优先于一切指令与档位。
- **跳过本幕**：一键作废当前指令（下一幕重新生成），并重置核验升级计数。
- **连败自动让步**：同一冲突连续 2 次玩家被顶回，第 3 次让玩家赢。
- **死亡抉择**：检测到主角死亡时弹窗三选一（视角转移 / 世界观内复活 / 剧终结算），无默认项；**未抉择前暂停注入**新指令。
- **做全书结算**（账本页底部，不依赖死亡的第二条结局路）：两段式 ——
  ① 确认后账本记 `收官请求`，**下一道指令由代码编排为收束幕**（回收剩余伏笔、收束主线，节拍取 `兑现伏笔`）；
  ② 演完后由你在面板**确认剧终**（也要二次确认）才停摆。**收官请求 ≠ 已剧终**：期间引擎照常推进、账本照常更新。
  重复点击幂等（`请求收官` 只认第一次，攒不出第二道收束幕）；「清除已剧终」会把 `收官请求` 与结算快照一并清掉，否则会一直出收束幕。
- **防剧透**（默认开，**两个独立开关**）：`折叠未引爆伏笔` / `折叠章回计划` 各自可关。
  **点被折叠的那一行即可临时揭示**（只展开那一条，再点收回；切页签/刷新全部收回，**不写盘**）。
  折叠**只发生在显示层**：账本里的伏笔内容、计划高潮与发给引擎的文本一条都不少（零截断红线）。
  旧的一刀切键 `防剧透` 保留为兼容来源（不再显示在 UI）：新键缺失时用它播种，新键存在则以新键为准。
- **冷启动**：开局前 3 轮只记账不下令，第 4 轮起注入指令。
- **群聊首版不支持**：检测到群聊即暂停并提示。

## 配置

### 接口

- **独立接口**：任何 OpenAI 兼容服务（地址末尾自动补 `/v1`），「获取模型列表」拉取后下拉选择；请求统一由酒馆服务器转发。
- **流式 / 预填充 / 温度 / 最大输出Token**。

### 导演

- **自动接管**、**更新频率**（每 N 条回复推进一次）、**读取最近回复数**。
- **提示条**（可观测性）：`全部（含开始）` / **`完成与异常`（默认）** / `仅异常` / `关闭`。
  **事件用提示条、状态用悬浮球** —— 选「关闭」只是不出声，球照样显示 编排中/出错/离线/剧终。
- **快照保留份数**（默认 **30**，可调 1~100）：删楼时账本可回退的楼层数；每份约几 KB~十几 KB，调大聊天文件变大。
- **高级（节奏与冷启动）**：**接管轮数**（默认 **4**：前 3 轮只记账不出指令，第 4 轮起编排本幕）、
  **连续高/低张力阈值**（默认各 **3**：连续 N 幕高张力强制喘息幕 / 连续 N 幕低张力安排「山雨欲来」）。
  这两个参数直接决定引擎的代码层规则，改完当轮生效（面板冷启动提示与引擎判定**读同一个值**）。
- **提示词开关**：破限 / 头部填充（可自定义文本）/ 防截断 / 预填充。
- **引擎读世界书**（与主 AI 相同激活逻辑）、包含全局世界书、世界书排除。
- **标签过滤**：处理发给引擎的回复（排除/只读指定标签）。

### 注入

- **事实层**：把常驻条目「**编剧备忘**」写进**按可用性解析出来的**世界书（蓝灯常开、防递归、切聊天重写、空则删）。
  落点顺序：① 角色卡主世界书（**先探测存在性**）→ ② 角色卡副世界书里**已有我们条目**的那本 → ③ 聊天世界书 → ④ 取/新建**专属聊天世界书**。
  **不盲写主世界书、不修改用户角色卡**：卡里 `extensions.world` 常会指向**未安装/改名**的世界书（链接悬空），
  这时 `getWorldbook` 会抛错——旧版直接写主世界书，于是**从来没写成功过**且错误对象是 `{}`（表现为静默降级）。
  现在悬空会被识别并**明确记一行"已回退到 X"**，全部目标不可用时**报出可读原因**（日志页 + 弹窗），不再伪装成正常。
- **只留一份**：落点会随绑定变化（悬空期落在聊天世界书 → 绑定修好后写回主世界书），所以**写完后会清理别处的旧副本**；
  关闭注入/剧终时**所有候选都撤**。否则主 AI 会同时读到两份、其中一份永远是陈旧的。
  设置页那个开关的文案与之一致：**优先写主世界书，不可读时自动回退聊天世界书，实际落点见日志页**。
- **指令层**：`injectPrompts` + `GENERATION_AFTER_COMMANDS`（`in_chat`, depth 0），生成前**幂等重注**，只读内存里已就绪的指令，**绝不 await 慢 API**。

### 与记忆插件共存（防混淆）

世界书里记忆插件提供的 `<记忆回溯>` 段落是**内容记忆**（剧情历史概要），不是世界设定、不是行动指令——引擎**不从中领取"必须推进的任务"**，**执行核验只针对最近正文**。导演的账本是**结构记忆**（戏演到哪了），两者互补不冲突。

## 数据存储

- **设置**：全局变量（键 `剧情导演_settings`）——接口配置等敏感信息**导出脚本不会携带**。
  **写回纪律（P1 事故后立的规矩）**：① **深合并子字段**（`接口`/`导演`/`标签` 等对象逐字段合并，**不是整块替换**）；
  ② **只写用户真正改动过的字段**（与"成功读到时的基线快照"比对，初始化/解析填充不落盘）；
  ③ **读失败绝不写回**（存储抛错/格式坏/解析失败 → 关闭写回闸门，宁可这次改动不生效，也不用默认值覆盖真数据）。
  三条都为了同一件事：**陈旧或残缺的内存副本不许覆盖存储里的密钥**。
- **剧情账本**：**楼层变量快照**（删楼/重roll/切分支自动回退，保留最近 N 份）；聊天变量（键 `剧情导演`）只存轻量索引（快照楼层 + 清空层）。严格按聊天隔离。
- **界面偏好**：全局变量（键 `剧情导演_界面`）——悬浮球位置/面板位置/主题；**同样只写改动过的字段**并与存储里那份合并（`insertOrAssign` 是整键替换，直接写会冲掉别的窗口刚改的值）。
- **离线熔断与已剧终**：聊天变量 meta（与「快照楼层索引」同一个键内）——空密钥/接口失败这类故障发生在**账本落盘之前**，
  存快照必丢，所以连败次数、最后失败原因与时间、自动暂停、已剧终都存这一层；**已剧终与账本字段双写**，
  删楼/回退撤不掉它（清空账本才会连它一起重置）。`指标`（指标账）随账本进楼层快照，删楼即回退。
- **零截断原则**：所有发送内容（引擎输入/编剧备忘/本幕指令）一律不截断；规模控制只做在源头（账本容量上限、读取范围）。结构键（章主题/对手名/角色名等短字段）有上限=格式守卫，内容字段（伏笔内容/赌注/下一步/契机/高潮事件/指令文本）零截断。

## 界面（风格 B「剧本批注」）

一本摊开在暗处的剧本、旁边搁一支红笔：**暖墨灰纸面 + 唯一的朱红**，衬线标题，层次靠**边线与留白**而不是阴影与圆角。

- **规范源码**：`docs/mockups/剧情导演-风格对比.html` 的 `.sB` 块（值照抄）；施工图 `docs/剧情导演-前端改版-风格B实现说明.md`；
  契约由 `tests/daoyan-style-b.test.ts` 钉住（改漂了会被用例抓住）。
- **颜色只在 `主题.ts`**：面板 CSS 一律 `var(--dj-*)`、**零硬编码色**，深浅两套主题键完全一致。
  语义色分工：**危险/剧终/数据异常 = `seal`（朱红）· 警告/强度 = `gold` · 成功/已执行 = `good` · 离线/冷启动 = `inkFaint`**；
  墨色五档 `inkStrong / ink / inkDim / inkFaint / inkGhost`（不再被一个 `seal` 一词到底）。
- **数字必须能被扫读**：数字容器一律 `var(--dj-num)` + `font-variant-numeric: tabular-nums`（指标、张力、核验、明细）；
  字号收敛成五级：16 指标数字 / 17 标题（衬线）/ 12.5 正文 / 11.5 次要 / 10 标签。
- **圆角一律 2px**（球仍是 40×40 的圆），**阴影只留一层**（画在 iframe 上，面板自身不叠第二层）。
- **设计在 460 名义宽下验证**：面板契约是 `面板机制.ts` 的 `panelW/panelH = 460/620`（**名义上限**，随视口取 min；窄屏 <700 走另一支），
  它写成 `.dj-panel` 的内联宽高、`box-sizing: border-box` → 量的是**面板本身**。对比稿画布写的 522 **不是契约**（别照抄）；
  真机量到的 iframe 更大，那是 `applyFrame()` 的"球∪面板 + 每边 4px"联合矩形，与面板尺寸不是一回事。
- **图标是内联 SVG**（`currentColor`、零依赖，不引 fontawesome/远程资源/远程字体）；卡片头用 `§` 批注记号而不是图标。
- **动效只回答动作**：页签/按钮/卡片 150ms 过渡；关键帧只有两条 —— 球的「编排中」呼吸环与状态条的回扫细条（都 1.6s）。
  `prefers-reduced-motion` 下动效全关，并把呼吸环换成**静态**朱红环（**换呈现，不换通道**）。
- **重点卡靠左边线分级**：普通卡左 2px `lineStrong`，判据卡与指令卡左 2px 朱红（用 `:has()` 选，不动 DOM）；
  状态条左 3px 用语义色 + 一个同色圆点。
- 仓库硬约束：禁 `vh`、无 `min-height`；**不新增滚动容器**（`overflow:auto` 只有既有的 `.dj-body` 与 `.dj-pre` 两处 ——
  改成 `hidden` 就是用 CSS 裁正文，违反零截断）；`position:absolute` 三处（球、面板、页签选中下划线的伪元素，
  最后一处照的是规范稿 `.sB`）。本插件是**独立全屏 iframe 浮层**（不是嵌在楼层里的界面），故 `fixed/absolute` 属形态必需。

## 面板（悬浮球仅作唤起器）

单击悬浮球（可拖动、位置记忆）弹出面板：

| 页 | 内容 |
| --- | --- |
| **本幕** | **状态条**（已剧终 / 引擎离线·连败 N 次 / 冷启动攒轮 / 运行中，离线与剧终优先于冷启动）、**指标卡**（§3 五项判据 + 张力波形，只读指标账）、张力读数与曲线、本幕指令预览 + **本轮代码规则触发记录**（张力曲线/契诃夫之枪/收束调度/余波/核验升级，只读 `指令.代码调整`）、活跃冲突、"跳过本幕"、"重新推进"、死亡抉择（"剧终结算"有二次确认）、已剧终后可"清除已剧终" |
| **账本** | 章回/伏笔/冲突/弧线；**修笔**（手动改状态，删中段楼后纠正）；剧终后顶部显示**全书结算**卡（只读 `指标.终值` 那一刻的快照，不重算）；底部**终局操作**区（做全书结算 / 确认剧终，都带内联二次确认） |
| **日志** | 最近一次引擎调用的完整请求/输出/报错 + 控制台 + 一键「复制报错发给助手」 |
| **设置** | 接口（含诊断与「测试连接」）、强度滑杆、红线、更新频率、快照保留份数、**提示条四档**、**高级（接管轮数 / 连续高·低张力阈值）**、标签过滤、提示词开关 |

## 可观测性（不用打开面板也知道在干什么）

起因是用户的一句话：「插件没弹窗，我不知道什么时候更新、什么时候更新完了、什么时候更新出错了，我还要进插件里看。」
排查结论是**机制在、事件不全、通道太弱** —— 于是定下：**状态用球（常驻、安静），事件用条（短暂、可关）**。

- **悬浮球五态**，优先级 `剧终 > 离线 > 出错 > 编排中 > 待命`（判定与 hover 文案都是纯函数，见 `球状态.ts`；面板只做绑定）：

  | 态 | 何时 | 呈现（环都在球**内**画，直径/层序/iframe 尺寸不变） |
  | --- | --- | --- |
  | `剧终` | `已剧终` | 朱红细环 2px + 字形转灰 |
  | `离线` | 熔断自动暂停 | `inkFaint` 虚线边 —— **离线不是危险，不用朱红吓人** |
  | `出错` | 上次推进失败、还没成功过 | 朱红环 3px，**常驻到下次成功**；期间用户点重推也保持（不被「编排中」顶掉） |
  | `编排中` | 引擎调用进行中 | 1.6s 呼吸环（reduce 下换静态环）；hover「正在编排本幕…」 |
  | `待命` | 其它（含冷启动记账） | 现状外观；hover 报最近节拍与几分钟前，或冷启动轮次进度 |

- **提示条四档**（`导演.提示条`，默认**完成与异常** ⇒ 每轮最多一条）。闸门设在 `toast.ts` 的 `showToast` 出口，
  所以「开始推进 / 完成 / 失败 / 熔断 / E1 未送达 / 快照没落盘」这些**既有调用点自动受同一档管**，不必各写一遍判断。
  「全部」才会每轮多一条 info；**「关闭」只静音事件，球状态照常工作**（球的判定不经过提示条这条通道）。
- **用时可见**：推进开始记时刻，完成提示与失败详情都带**用时**（`编排完成：本幕节拍 → 兑现伏笔 · 用时 48s`），
  慢的时候用户知道是在等、不是卡死。档位同步有三个入口：启动时（`index.ts`，面板没打开也生效）、每轮推进（`update.ts`）、设置页 `@change`。
- **面板辅助通道**：`编排中` 期间状态条下补一条**不确定态细进度条**（只表示“在跑”，不表示真实百分比）。
- 规格：`docs/剧情导演-可观测性-提示条规格-v1.md`；用例：`tests/daoyan-orb-status.test.ts`。

## 安装

1. 运行 `pnpm build`（或 `pnpm watch`）生成 `dist/剧情导演/index.js`；
2. 在酒馆助手中新建脚本，内容填 `import 'http://localhost:5500/dist/剧情导演/index.js'`（实时监听）或直接粘贴打包产物，启用；
3. 页面出现悬浮球，点击进入面板，在「设置」里配好接口后即可开始。

无脚本按钮——所有操作都在面板里。
