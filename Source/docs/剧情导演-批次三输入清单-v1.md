## A. 节奏类

### A1. 高潮**间隔偏长**（结论经两次修正，**现为批次三头号输入**）
- **证据（R21–R36 综合）**：四次「高潮」出现在楼 **26 / 50 / 70 / 76**，**全部由引擎自选、非任何规则强制**；
  间隔约 **20~24 楼**；且 **4/4 每次高潮后都紧跟「余波」指令**（`代码调整`="高潮后必有代价"）——**该规则 100% 可靠触发**。
  张力峰值：楼46=**9** / 楼70=**8** / 楼50=7。
- **结论演进**：早前"高潮**不可复现**"→（楼50）→"可复现但**间隔不可控**"→（楼76）**"能复现，但间隔偏长（~20 楼）"**。
- **候选改动**：**可选**加"**高潮间隔上限**"规则（连续 N 幕无高潮 **且** 冲突已达某阶段/张力达阈值 → 强制「高潮」）。
  成本低（一条规则 + 用例）；风险：与"高潮后必有代价"/"张力曲线"的优先级需明确。
- **dsh 建议**：**先不做**。引擎自己会给（4 次已证），但**若你要"稳定节奏"、不愿等 20 楼**，这条值得做。

### A2. 高潮后的"平走"（
- **证据**：高潮@50 → 张力 7→5 平台、节拍连续 6 连「兑现伏笔」+ 余波，约 16 楼无新峰；**此前 6 连兑现伏笔期间无受挫**。
- **候选改动**：**"先落再抬"**节奏约束（高潮后必须经历一次明确低谷，再允许回升），或限制"连续兑现伏笔"的幕数上限。
- **dsh 建议**：**优先级次于 A1**，但如果你觉得"读起来平"，这条更直接对准体感。

## B. 质量控制类（都不是插件缺陷，但插件可"提示"）

### B1. 不完整输出被照单全收 —— **已确认成立，共 5 例**
- **证据**：楼 48 缺 1 类块 / 52 缺 2 类块 / 62 `<JSONPatch>` 畸形 / 64 缺全部块(3.9k) / **66 缺全部块且无 thinking(1.1k)**。
- **插件当时行为**：**全部照常推进**（读叙事、写快照）—— 这是**设计如此**（插件不依赖卡片变量块）。
- **候选改动**：
  - **自动闸门**（拦推进）：**只做"与标签无关"的轴**——① 宿主"生成被中止"事件；② 正文结尾判定（剥任意 `<X>…</X>` 块后是否收尾）。
  - **可选非阻塞提醒**（推荐）：学**最近 N 层**的**块集合 + 字数分布**，本层显著缺项/明显偏短 → **只 warning + 记日志，不拦推进**。
- **dsh 建议**：**自动闸门做小**（只轴①，宁可漏判不误判）；**提醒做成可选**（默认开或关由你定）。
  规格已备：`docs/剧情导演-坏楼层防护-规格-v1.md`（附则 2/3/4 已写清"标签名不可写死""双轴""退化独立类"）。

### B2. 长上下文输出退化（**本轮最有价值的发现**）
- **证据（2026-10-07 06:05 更正为"间歇性"）**：楼 48/52/62/64/66 连续出现退化（缺 1 块 → 缺 2 块 → JSON 畸形 → 缺全部 3.9k → 缺全部 1.1k 无 thinking），
  但**楼 68 恢复完整**（8232 字、thinking+branches+UpdateVariable）、**楼 70 又缺 `<UpdateVariable>`** →
  **不是单调下滑，而是"间歇性退化、在该段偏密"**；存在**自愈能力**，非不可逆。
- **定性**：**模型/预设/长上下文**层问题，**非插件**；但会**降低引擎分析素材质量**（账本质量随之下降）。
- **候选**：① 报告里单列，供你在**预设/模型侧**处理（换模型、调上下文策略、定期新开聊天或做摘要）；
  ② 插件侧可加的只是 B1 那个"提醒"。
- **dsh 建议**：**不改插件**，作为**环境建议**给你。
