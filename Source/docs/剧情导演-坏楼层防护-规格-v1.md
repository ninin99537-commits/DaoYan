# 剧情导演 · 坏楼层防护规格 v1（生成中止 / 截断）

> 来源：用户 2026-10-07 指令——「酒馆的 AI 可能会卡死导致一直不输出然后自动停止，或者输出一半没输出完截断了，我们的插件发现楼层输出完了就推进了，其实楼层输出的不对。」
> **状态：先读规格，暂不动手**——dsh 会在通宵试玩里用真机证据确认判定口径（信号源与阈值）后再放行。

---

## 1. 已确认的缺口（dsh 读码，无需重复查）

| 事实 | 位置 |
| --- | --- |
| 插件只按"有新楼层"推进，**不检查楼层内容** | `index.ts:107` `onMessageReceived` + 防抖（只处理最后一条） |
| `update.ts` 里的"截断"**全是判引擎 JSON**，与酒馆正文无关 | `update.ts:234-249` |
| **坏楼层会被照单全收**：分析 → 写账本 → 写楼层快照 | `update.ts` 主流程 |
| 救法已存在：**删楼/重roll/切分支 → 账本自动回退** | `快照.ts:6` 注释 + `discardSnapshotAt(floorId)` |

**结论**：楼层坏了，插件不会知道，会把它当成"演完了这一幕"记账；用户只能删楼重写（此时账本会回退，机制是好的）。

---

## 2. 目标

**疑似"未写完/被中止"的 AI 楼层 → 不静默推进**，而是：**识别 → 提示 → 跳过自动推进 → 保留手动覆盖**。
不改变"正常楼层照常自动推进"的既有行为。

---

## 3. 识别（两路信号，优先用宿主事件）

**A. 宿主事件（强信号，优先）**
请先查 `@types` 暴露了哪些生成相关事件与状态（如生成被中止 / 生成结束 / 是否正在生成）。
- 若能拿到**"本次生成被中止/停止"**这一类信号 → **单独成立**即判定疑似；
- 若只拿到"是否正在生成"（`is_generating`）→ 推进时仍在生成中应跳过（现有防抖已部分覆盖，但**不足以**判断"停了且没写完"）。

**B. 启发式（兜底，两个条件同时满足才判疑似）**
1. 该 AI 楼层正文**异常短**（建议阈值 **< 80 字**；本场戏正常 AI 楼层 2000–14000 字，<80 几乎必是坏的）；
2. **且**结尾**无终止标点**（结尾字符不属于 `。！？…"』）】` 之一）。
> 只用 B 时**必须两条同时满足**，避免误伤正常的短回复。
> **只对 AI 楼层判定**（不判用户层/系统层）。

**C. 不采用**"与上一层高度重复"作为判据（重 roll 场景误报率高，且防抖已处理）。

---

## 4. 处理

1. **跳过自动推进**，并**不写账本快照**（与"没推进"等价）；
2. `toastWarning('本层疑似未写完/被中止，已跳过推进；确认无误可点「重新推进」')`（归"异常"档，受提示条档位控制）；
3. **日志页写一行**，含**判定依据**（如"正文 42 字且结尾无终止标点"或"宿主报告生成中止"）；
4. **手动覆盖**：面板「重新推进」（force 路径）**照常可用**，用于"确认这层没问题、就是要推进"；
5. **球状态**：走既有 `出错` 态（语义＝"有需要你处理的问题"），悬停文案说明"本层疑似未写完，已跳过推进"；
6. **删楼回退不变**（`discardSnapshotAt` 已有，保持）。
7. **不新增设置项**：默认开启、阈值固定。若真机出现误伤，再由用户决定是否加开关。

---

## 5. 用例

① 短正文（<80 且无终止标点）→ 跳过 + warning + **不写快照** + 日志含判定依据；
② 正常正文（长、有终止标点）→ **照常推进**（不回归）；
③ **正常短回复**（<80 字但结尾有句号）→ **不跳过**（防误伤）；
④ 用户层/系统层不被判定；
⑤ `force`（手动重新推进）→ 即使疑似也推进；
⑥ 宿主"生成被中止"信号 → 单独成立（不依赖长度）；
⑦ 跳过时**球状态 = 出错** + 悬停文案含"已跳过推进"。

---

## 6. 边界

- **不改防抖语义**、不改其它自动推进分支、不改删楼回退；
- **零截断**：这是"不把没写完的东西当写完"，与"不截断正文"同源，别把判定做成"截掉正文"；
- 判定失败（拿不到宿主信号 + 无法判定）时**保持现状**（照常推进）——**宁可漏判，不要误判**（误判会让用户以为插件坏了）。

---

## 附：一类**不是**坏楼层的情况（用户 2026-10-07 确认）

助手楼层**尾部**可能出现一段**循环模板**（实测形如 `<Reference_Example>` 内反复 `No.` / `The user is asking a scientific/medical question.` / `===`，
单层重复 30~40 次、4~4.6k 字符）。经用户确认：**这是预设里刻意的「抗截断」手法**（循环自我终止），**不是截断、不是缺陷**。

→ 因此判定"疑似未写完"时**必须先剥掉这类块**（`<Reference_Example>…</Reference_Example>`、`<thinking>`、状态/变量块等），
   只看**叙事正文**的结尾；否则每一层都会被误判（dsh 的工具 `check-floor.py` 就踩过这个坑：楼 42/44 均被判"未收尾"）。

### 附则 2（2026-10-07 用户提醒）：**标签名不可写死**

用户会**更换抗截断手法**——"包裹的标签可能会不一样"。因此：

1. **首选宿主事件**（生成被中止/停止）作为判定依据：**与标签无关**，最稳；
2. 若必须走文本启发式：
   - **优先用酒馆自己的"按正则格式化后的显示文本"**（TavernHelper 暴露了 `formatAsDisplayedMessage` / `formatAsTavernRegexedString` 一类接口）
     —— 这样"什么算叙事"由**用户自己的正则配置**决定，插件**不猜标签名**；
   - 退而求其次：**通用剥块**——剥掉任意 `<X>…</X>` 成对块（X 为任意标识符）+ HTML 注释，再判结尾。
     **禁止**只枚举已知标签（`Reference_Example` / `thinking` / `UpdateVariable` …）——那会在用户换手法后立刻失效；
3. **保持"宁可漏判，不要误判"**：判定失败 → 照常推进（现状），并给手动覆盖。

## 附：**结构化输出缺块/畸形**（实测三例，2026-10-07 通宵试玩）

| 楼层 | 形态 | 后果 | 插件当时行为 |
| --- | --- | --- | --- |
| 48 | 缺 `<UpdateVariable>/<JSONPatch>`（**叙事完整**） | 卡片 MVU 变量不更新 | 照常推进（正确：只读叙事） |
| 52 | 缺 `<branches>` + `<UpdateVariable>` | 同上 + 分支信息缺 | 照常推进 |
| 62 | `<JSONPatch>` **畸形**（缺 `,"value":`、数组尾多逗号） | **卡片变量更新解析失败** | 照常推进 |

**这不是"截断"，是"结构化输出坏掉但叙事完整"** —— 比截断更隐蔽：**读起来是完整的一幕，但卡片的变量/状态已经不更新了**。

**为什么暂不纳入自动闸门**（dsh 裁定）：
- 这些块是**卡片专属**的（`meow_FM`/`branches`/`UpdateVariable`…），硬编码会被用户换预设打破（违反本规格附则 2"标签名不可写死"）；
- 该卡片的块本就**间歇出现**（实测），按"缺块即坏"判定会**大量误报**。

**若用户要求（可选、非阻塞）**：做一版「**结构化输出健康度提醒**」——学最近 N 层出现过的顶层块集合，
某块在近期高频出现而本层缺失/畸形时，**只弹一条 warning + 记日志**，**不拦推进**（守"宁可漏判，不要误判"）。

### 附则 3（kilo 2026-10-07 实测建议）：判定**双轴**，但只有一轴能进自动闸门

实测 4 例不完整输出（楼 48/52/62/**64**）显示两种坏法并存：

| 轴 | 表现 | 能否进自动闸门 |
| --- | --- | --- |
| **① 叙事轴**：是否断在半句 / 生成被中止 | 楼 64 **叙事完整**（只是块被剥掉）→ 这一轴**抓不到它** | ✅ **能**（宿主中止事件 + 正文结尾判定，标签无关） |
| **② 结构轴**：结构化输出块是否齐全 / 是否畸形 | 缺块 / 缺分支 / JSON 畸形 / 全缺 | ❌ **不能直接进**——块名是**卡片专属**（`meow_FM`/`branches`/`UpdateVariable`/`Status`…），且该卡片本就间歇出现 |

**结论**：自动闸门只做轴①；轴②落为**可选的、非阻塞的**「结构化输出健康度提醒」——
**学最近 N 层出现过的顶层块集合**（不预设任何名字），某块近期高频出现而本层缺失/畸形时**只 warning + 记日志，不拦推进**。

## 附则 4（kilo 2026-10-07 实测）：**「输出质量退化」应作为独立类**（与"截断"并列）

**5 例梯度**（同一场对话、长上下文下，越往后越差）：

| 楼层 | 缺失/异常 | 字数 |
| --- | --- | --- |
| 48 | 缺 1 类块（`UpdateVariable/JSONPatch`） | 正常 |
| 52 | 缺 2 类块（`branches`+`UpdateVariable`） | 正常 |
| 62 | `<JSONPatch>` **畸形** | 正常 |
| 64 | **缺全部结构化块** | 3.9k |
| **66** | **缺全部结构化块 且 无 `<thinking>`** | **1.1k** |

**与"截断"的区别（为什么必须单列一类）**：
- **截断**＝内容没写完（半句、被中止）→ 有**与标签无关**的判据（宿主事件 / 结尾判定）→ **可进自动闸门**；
- **退化**＝内容"写完了但很薄/结构被剥" → 正文**仍可读**、**插件无法据此判坏** → **绝不能进自动闸门**（会大面积误伤正常短回复）。

**处置**：
1. **自动闸门不做**（保持"宁可漏判，不要误判"）；
2. 归入**可选、非阻塞**的「输出健康度提醒」：学**最近 N 层**的**块集合**与**字数分布**，
   本层若"块集合显著缺项"或"字数远低于近期分布下沿"→ **只 warning + 记日志**；
3. **这是模型/预设/长上下文层的问题，不是插件缺陷** —— 报告里单列，并附"它会降低引擎分析素材质量"的说明。

## 附则 5（2026-10-07 dsh 自曝的假缺陷）：**剥标签必须"只删确定非叙事的块"，其余只去标记**

**事故**：dsh 的检测工具用"**通用剥块**"（`<X>…</X>` 一律整块删）→ 而整条消息被包在 `<Interleaving>…</Interleaving>` 里时，
**外层包裹标签把里面的叙事一起吃掉** → 工具报"楼86 字数=0"，看起来像"插件接受了空楼层"的严重缺陷；
**核实原文**：楼86 raw 8538 字、剥块后仍有 **2702 字正常叙事** → **插件推进正确，纯属工具误报**。

**因此本规格的实现要求（收紧）**：
1. **只整块删除"确定非叙事"的块**：`thinking` / `Reference_Example` / `disclaimer` / `UpdateVariable` / `JSONPatch` / `branches` / `meow_FM` / `StatusPlaceHolderImpl` / `time_format` / HTML 注释；
2. **其余标签一律"只去标记、保留内部文本"**（**绝不整块删**）——未知标签的内部宁可当叙事；
3. **空体判定要显式**（注意 `'' in 任意字符串` 恒为真这种坑）；
4. 结论不变：**宁可漏判，不要误判**。**过于激进的文本启发式会把正常楼层误判成坏楼层**——这条比"漏掉一个坏楼层"更糟。
