# 「剧情导演」完善任务 · 终验标准（dsh 策划，2026-10-07）

> 验收标准（用户原话）：**让酒馆AI能写出真正的跌宕起伏的剧情**——行为级标准。
> 本文把它拆成可判定、可复核的三层，明确"什么算通过、证据是什么、边界在哪"。**最终由用户确认收货。**

## 0. 三层验收结构

| 层 | 验什么 | 谁出证据 | 判定 |
| --- | --- | --- | --- |
| **L1 方案项落地**（客观） | 批次一/二逐项实现正确（H/I/F/K/J/D/E/代码调整上面板/弧线终态枚举化）+ 工程门槛 + 不回归 | xiaoxi 交付 + dsh 审查 | dsh 审查逐项 PASS/FAIL |
| **L2 判据达标**（半客观） | 五项判据（伏笔回收率/张力波形/冲突升级/真实挫折/指令执行率）双轨测量 | kilo 实测（账本自动统计 + 抽样人工核验） | 对达标线；先基线后定线 |
| **L3 用户体验**（主观但决定性） | 真实游玩的"跌宕起伏"体感 | 用户抽读测试正文 + 开/关插件盲评 | **用户同意** |

**通过规则**：
- L1 全 PASS + L2 达标 → L3 用户确认 = **通过**
- L1 有红项 → 不通过（反馈实现方修，复验）
- L2 未达标但 L3 通过 → **记录为批次三改进项**，由用户决定是否接受（不擅自判失败）
- L3 不通过 → 回到批次三（A 引擎提示词 / B 服从性），带实测数据迭代

## 1. L1 明细（引用现有清单，不重复）

- **批次一**：`docs/剧情导演-批次一审查清单.md`（8 组：G 协议 / H / I / F / K / J / 不回归 / 工程门槛）
- **批次二**：D 冷启动提示 / E 张力阈值与接管轮数配置化 / 代码调整上面板 / 弧线终态枚举化——交付时按同一清单格式逐项核
- **工程门槛**（每次交付都跑）：`pnpm build` 成功 / `pnpm test` 全绿 / `tsc` 0 新错 / 平台直连 0 处 / README 同步 / 命名取 GLOSSARY
- **不回归红线**：零截断（用户红线）；双层注入与去重纪律；快照回退；死亡抉择状态机；冷启动语义

## 2. L2 明细（判据与证据）

判据定义与操作化见 `docs/剧情导演-测试方案-v1.md` §3；达标线为草案，**先跑阶段一基线再校准**。

| 判据 | 达标线（草案） | 证据来源 | 备注 |
| --- | --- | --- | --- |
| 伏笔回收率 | 全程 ≥2/3（附绝对数） | `账本.指标.章节统计` + 抽样核验"消亡"是否合理 | 小样本聚合全程 |
| 张力波形 | ≥2 次明显起伏（峰谷差≥3） | `账本.指标.张力历史` | 结论限定"系统整体有波形"（部分由代码规则产生） |
| 冲突升级 | 每个活跃冲突 ≥2 次阶段推进 | `账本.指标.章节统计.冲突推进数` | 冲突<1 记 N/A |
| 真实挫折 | 档3 下 ≥1 次/10 轮 | 节拍历史（代理）+ **抽样正文人工核验** | **以人工为准** |
| 指令执行率 | ≥70% | `账本.指标.核验` + **人工判定** | **以人工为准**；连续 2 次未执行=异常样本 |

**两阶段环境（用户已定）**：
- **阶段一（10 轮，记忆插件关）**：验通电 + 拿基线。**结论按"无内容记忆环境"表述**——此时双方只剩最近几层记忆，**编剧备忘是唯一长线载体**；若伏笔仍能跨轮兑现，说明账本真的承担了长线记忆（比开着记忆插件更强的证据）。
- **阶段二（记忆插件开）**：验共存（E6/E7）+ 真实环境效果。

## 3. L3 明细（用户体验，最终裁决）

1. **盲评**（kilo 组织）：阶段一开插件 10 轮正文 vs 关插件 10 轮正文，**不告知来源**，用户抽读并回答"哪段更跌宕、为什么"。
2. **体感确认**（dsh 汇总后问用户）：伏笔是否让你有"原来如此"的回收感？主角是否真的输过/付出过代价？节奏有没有"压—爆—喘"？
3. **用户一句话结论**：接受 / 不接受 / 有条件接受（附条件）。

> 这一层不可替代：判据再漂亮，用户玩着"不平淡"才算数；反之判据差一项但用户体感好，也应记录为"主观通过 + 客观待改进"。

## 4. 证据清单（可复核，缺一不可）

- ☐ `docs/剧情导演-测试记录-<日期>.md`：逐轮表（节拍/核验/张力/伏笔变化/冲突阶段/引擎调用/**编剧备忘存在性**/引擎耗时）+ 阶段汇总
- ☐ 面板"指标"卡截图或读数（五项判据）
- ☐ 日志页保留的引擎请求/输出/报错（至少抽样）
- ☐ 起手剧情 + 设置快照（保证可复现）
- ☐ 迁移证据：用户现有 v1.0 聊天升级后**不崩、不清空**（R-K3 实证用例）
- ☐ dsh 的 L1 审查记录（批次一/二逐项结论）

## 5. 已知边界（诚实声明，写进给用户的结论里）

1. **插件是概率性引导，不是强制**：主AI可能仍不执行指令；核验只能"发现 + 升级（封顶 2 次）"，无法强制它的笔。
2. **判据是代理指标**：「真实挫折」「指令执行率」本质靠引擎自报，**以人工判定的抽样为准**。
3. **样本量有限**：阶段一 10 轮 ≈ 1 章、2~3 条伏笔；"每章回收率"统计功效低，故聚合到全程并附绝对数。
4. **张力波形部分是代码规则的产物**（节拍折算 + 强制喘息/阴影），不能全部归功于引擎文案质量。
5. **未验证项**：群聊边界（首版不支持）、超长聊天的快照体积、多角色卡场景。
