# 剧情导演 · 防剧透改造 + 手动全书结算 规格 v1

> 来源：用户两问（2026-10-07）——「伏笔账看不到内容，不能弄个设置吗？」「怎么样才会走到结局呢？」
> 定位：**同一批文件**（`悬浮球界面.vue` / `schema.ts` / `引擎规则.ts` / `update.ts`），因此**排在风格 B 与可观测性之后**，不并行改。

---

## 一、现状（读码结论，供对照）

**防剧透**
- `schema.ts:79` `防剧透: z.boolean().default(true)` —— **默认开**，这是用户"看不到伏笔内容"的直接原因
- `悬浮球界面.vue:149` 未引爆伏笔内容 → 显示「（防剧透已折叠内容）」
- `悬浮球界面.vue:136` 章回计划高潮 → 显示「（防剧透已折叠）」
- 缺点：**一刀切全局开关**，想看一眼某条就得全部摊开

**结局**
- `章回进度 = 铺垫 / 推进 / 收束 / 已完结`；**「已完结」由引擎产出**，只代表"这一章完了"，随后会开下一章
- 引擎产出里**没有"收官/全书完结"字段** → 它无法宣布全书结束
- 唯一结局路径：主角死亡 → `待决死亡=true`（暂停注入）→ 面板三选一（视角转移/世界观内复活/**剧终结算**）→ 二次确认 → `写已剧终(true)` → 自动路径整体停摆；「清除已剧终」可恢复
- **结论：活着的角色走不到结局** —— 这是设计缺口

## 二、规格 A：防剧透改造

### A1. 拆成两个开关（各自独立）
```ts
// schema.ts（导演设置）
防剧透伏笔: z.boolean().default(true),   // 折叠「未引爆」伏笔的 内容
防剧透章回: z.boolean().default(true),   // 折叠「章回.计划高潮」
```
- **迁移**：保留旧键 `防剧透`（**不再在 UI 显示**，`z.boolean().optional()`）作为兼容来源——
  装载时若新键缺失，则用 `旧防剧透 ?? true` 播种两个新键；之后一律按新键工作。用例钉住这条迁移。
- 设置页文案：`防剧透 · 折叠未引爆伏笔` / `防剧透 · 折叠章回计划`（两项分开，各自可关）。

### A2. 点击临时揭开（核心改动）
- 折叠态显示「（防剧透已折叠内容）」+ **一个"揭开"小图标**（内联 SVG，照 §4 规范）；
- **整行可点击**：点一下 → **该条就地展开**显示真实内容，图标换成"合上"；再点收回；
- **只影响被点的那一条**，其它条目保持折叠；
- **展开状态不持久化**（内存态：切页签/刷新/换聊天即回到折叠）——防剧透仍是默认行为；
- 章回计划高潮同样处理（点「（防剧透已折叠）」→ 显示计划高潮文本）。
- 无障碍/可点性：`cursor:pointer`、`title` 提示"点击临时揭示（不写盘）"、键盘可达（可聚焦 + Enter/Space）。

### A3. 用例
① 两个开关独立生效（伏笔折叠但章回显示、反之亦然）；② 点击只揭开该条，其余仍折叠；
③ 展开态不落盘（重载后回到折叠）；④ 旧键 `防剧透:false` 迁移 → 两个新键都为 false；旧键缺失 → 都为 true。

## 三、规格 B：手动全书结算

### B1. 入口与防误触
- 位置：**账本页底部**，与「清空账本」同一区（都是终局操作），按钮文案 **「做全书结算」**，`danger` 样式；
- 点击 → **面板内联二次确认**（与死亡抉择的「确认剧终结算」同款形态），确认文案要写清后果：
  「将编排一幕**收束幕**（回收剩余伏笔、收束主线），演完后由你确认落幕；剧终后自动路径停摆（可清除已剧终恢复）」。

### B2. 两段式（尊重"引擎产出 / 代码编排 / 用户拍板"的分工）
**第一段（代码编排）**：确认后
1. 账本写入 **`收官请求 = true`**（新增字段，`boolean` 默认 false；迁移默认 false）；
2. **构造本幕指令走收官分支**：产出一幕「收束幕」的指令——要求：收束主线冲突、**尽可能了结剩余伏笔**（与契诃夫之枪同精神）、给一个**不总结、不升华**的收尾、留余味；节拍取值在既有枚举内选最合适的（建议 `兑现伏笔` 或 `余波`，**请在 INFO 里说明你的选择与理由**）；
3. 该指令按既有路径注入，**下一轮**由主 AI 演出收尾幕。
**第二段（用户拍板）**：收官请求存在期间，面板**常驻**显示「**确认剧终**」按钮 →
点击（二次确认）→ `写已剧终(true)` → **自动路径整体停摆**（既有语义，不新增开关）。

> 不硬性要求引擎必须产出 `章回.进度='已完结'`：**落幕由用户确认**，引擎只是把这一幕演好。

### B3. 判据终值存档 + 结局成绩单
- 剧终时把 `计算判据()` 的结果快照进账本 **`指标.终值`**（新增字段，`object | null`，默认 null；**迁移默认 null**）；
- 剧终后**账本页顶部**显示「**全书结算**」卡片：章数 / 伏笔总量与回收率 / 张力峰谷与起伏次数 / 受挫次数 / 冲突推进 / 指令执行率（读 `指标.终值`，**不重新计算**，保证"落幕那一刻的数字"可复现）。
- 未剧终时不显示该卡片。

### B4. 与既有机制的关系（必须守住的边界）
- **收官请求 ≠ 已剧终**：收官期间引擎照常推进、账本照常更新；只有用户确认后才停摆；
- **不改死亡路径**：`待决死亡` 三选一（含「剧终结算」）**保持原样**，本规格只是**新增一条不依赖死亡的路径**；
- **可逆**：既有「清除已剧终」仍是唯一恢复入口，且清除后 `收官请求` 也应被清（否则会一直出收束幕）——请在 INFO 里说明你怎么处理；
- **幂等**：重复点「做全书结算」不应产生多道收官指令（用 `收官请求` 门控）。

### B5. 用例
① 未剧终时无结算卡片；② 确认结算 → `收官请求=true` 且下一道指令是收束幕（节拍/要求可断言）；
③ 收官期间引擎照常推进、账本更新；④ 确认剧终 → `已剧终=true` + `指标.终值` 有值 + 卡片出现；
⑤ 清除已剧终 → 自动路径恢复且**不再出收束幕**；⑥ 重复点击不产生多道收官指令；⑦ 迁移：老账本无 `收官请求`/`终值` → 默认 false/null，不崩。
