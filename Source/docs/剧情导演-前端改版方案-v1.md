## 1. 现状诊断：为什么显得丑

**投入对比（同族界面文件大小）**

| 插件 | 界面文件 | 体积 |
| --- | --- | --- |
| 彼方（NPC 幕后生活） | `悬浮球界面.vue` | 113.5 KB |
| 烟火（世界运转） | `悬浮球界面.vue` | 103.1 KB |
| 正文美化 | `设置界面.vue` | 56 KB |
| **剧情导演** | `悬浮球界面.vue` | **36.8 KB** ← 最少 |

→ 结论：**不是审美差，是投入少**——家族的界面语言（设计令牌、卡片体系、空态/错误态、动效）在另两个插件里已经存在，本插件只做了功能骨架。

**当前界面构成（源码实扫，30 个 `dj-*` 类）**
`dj-root / dj-orb / dj-panel / dj-tabs / dj-body / dj-status-h / dj-metrics / dj-metric / dj-card / dj-card-h / dj-sec / dj-field / dj-input / dj-select / dj-btn / dj-mini / dj-tag / dj-check / dj-pre / dj-tension / dj-tension-v / dj-spark / dj-row / dj-inline / dj-actions / dj-hint / dj-muted / dj-empty / dj-err-line / dj-theme / dj-sub / dj-p`

**待逐项确认的嫌疑点**（改版时先核对再动手）
1. **无设计令牌**：颜色/间距/圆角/字号散落在各处，导致观感"糊"、不成体系；
2. **层级扁平**：三态状态条、指标卡、各卡片视觉重量接近，一眼看不出主次；
3. **状态态缺失**：空态（`dj-empty`）、错误态（`dj-err-line`）样式简陋；离线段缺少醒目的降级提示；
4. **无图标/无动效**：四页签与按钮缺视觉反馈（hover/active/切换过渡）；
5. **数字不可扫读**：指标卡是判据的门面（回收率/张力峰谷/执行率），应做到"一眼读到"，必要时给数字用等宽字形。

## 2. 硬约束（违反即不予验收）

**A. 仓库规范**（`.cursor/rules/前端界面.mdc`）
- ❌ 禁用 `vh` 等受宿主高度影响的单位；高度用 `width` + `aspect-ratio` 推导；
- ❌ 避免 `min-height` / `overflow: auto` 之类**撑高父容器**的属性；
- ❌ 主体内容不得 `position: absolute` 脱离文档流；页面必须有外部支撑；
- ❌ 不得产生横向滚动条；要适配容器宽度；
- ⚠️ "卡片形状就不要背景色，除非用户明确要求"——本插件面板是**浮层**，需要一块底以脱离酒馆背景，**这条要用户明确授权**（见 §6）；
- ✅ 样式写在 vue 的 `<style lang="scss">`；图标可用 **fontawesome 免费图标**。

**B. 插件自有关口**
- **不改 DOM 契约**：`dj-*` 类名与结构是逻辑与**用例的锚点**（`tests/` 里有源码级断言）；若必须改结构，**同一提交内同步更新用例**；
- **不改尺寸契约**：悬浮球 40×40、面板 522×628（实测）由 `悬浮球界面.ts` 与宿主协商；改尺寸要同步改那边；
- **零依赖**：纯 CSS + 现有 Vue，**不得引入外部 CDN / 远程字体 / 新 npm 依赖**（插件在酒馆 iframe 内运行，远程资源不可靠）；
- **零截断红线不动**：样式不得用 CSS 隐藏正文内容来"美化"（信息可以被折叠交互，但不能被静默丢弃）。

**C. 功能不得回退**
- 三态状态条语义（已剧终 > 引擎离线 > 冷启动攒轮 > 运行中）**优先级与文案含义不变**；
- 指标卡数字必须仍来自同一数据源（改版只动呈现，不动取值）；
- 设置页字段与既有全局变量存储路径不变。

## 3. 目标与验收

**目标（按重要性）**
1. **一眼可辨**：状态条四态、指标卡五判据、当前指令预览，三者的主次关系清晰；
2. **协调**：在酒馆深色环境里不突兀（不刺眼、不灰糊），选中/悬停/禁用态齐全；
3. **可信**：数字等宽对齐、单位与阈值可读；异常态（如判据 `>100%?`）显眼而不吓人；
4. **流畅**：页签切换、面板展开/收起有轻量过渡（≤200ms，不拖慢）。

**验收方式（三层）**
- **L1 规范符合**：逐条对照 §2 硬约束（我会逐条核，含 grep `vh`/`overflow`/`position: absolute`）；
- **L2 真机**：kilo 在你机器上截"改版前 vs 改版后"同尺寸对比图；`pnpm test` 全绿（含界面断言）；
- **L3 体感**：**你**看一眼说"不丑了"——这是这阶段的最终判据（与主任务的 L3 同性质）。

## 6. 待用户确认（开工前需要）

1. **风格方向**：三选一或另提——
   - (a) **极简线性**：细线、留白、低饱和，最安全；
   - (b) **深空 HUD**：等宽数字、细描边、微光扫描线——**与你的机甲/深空故事最搭**；
   - (c) **日式轻小说卷轴**：衬线标题、纸质纹理、章节感——与主 AI 的文风同调。
2. **是否授权"面板带底色"**：仓库规范默认卡片不带背景色，但浮层需要一块底以脱离酒馆背景（我建议授权，否则面板会与聊天文字糊在一起）。
3. **范围**：只美化 **剧情导演**，还是**顺便统一家族三件套**（彼方/烟火）的视觉语言？
4. **主题跟随**：是否需要跟随酒馆明/暗主题？（现在是 `dj-theme` 一处，建议做双主题令牌）

## 7. 附：本方案不做什么

- 不改引擎/提示词/判据/注入（那是主任务与批次三的事）；
- 不重写组件逻辑、不换框架、不引入 UI 库；
- 不为了好看而隐藏信息（信息可折叠、可收纳，但不可丢弃）。
