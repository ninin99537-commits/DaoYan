# 剧情导演 · 可观测性规格：提示条 + 悬浮球状态 v1

> 用户原话：「插件没弹窗，我不知道什么时候更新、什么时候更新完了、什么时候更新出错了，我还要进插件里看。」
> 结论：**机制在、事件不全、通道太弱**。本规格要把"外部编剧在干什么"变成**不用打开面板就知道**。

---

## 1. 现状（2026-10-07 实机核查）

| 事实 | 证据 |
| --- | --- |
| 提示条设施**已存在且工作** | 酒馆页 DOM 里 `#dj-toast-stack` 存在、挂在**父页面**、`position:fixed`、`z-index:2147482998`、主题变量已注入 |
| 成功/失败**本来会弹** | `update.ts:317` `toastSuccess('本幕节拍 → X')`；`update.ts:339` `toastError('推进失败…')` |
| **"开始推进"没有提示** | `update.ts:219` 只有 `console.info('开始推进…')`，**无 toast** |
| 提示条容易错过 | 右下角（实测 `x=1579,y=913`）、宽 ≤380px、success/info 仅停 **3.4s** |
| **悬浮球没有任何状态** | 球只有"开/关"两种外观，看不出"正在编排 / 上次出错 / 已暂停" |

→ 用户必须打开面板才能知道状态，是**设计缺口**，不是 bug。

---

## 2. 目标（三条问题各给一个答案）

| 用户的问题 | 由谁回答 |
| --- | --- |
| 什么时候**在**更新？ | **悬浮球"编排中"状态**（常驻可见，零噪音） |
| 什么时候更新**完**了？ | 提示条（可配）+ 球回到待命 |
| 什么时候**出错**了？ | 提示条（error，8s）+ **球进入"出错"状态并保持**到下次成功 |

**设计原则**：**状态用球（常驻、安静），事件用条（短暂、可关）**。不要把每轮都变成弹窗雨。

---

## 3. 规格 A：悬浮球状态机（主通道）

球新增 `data-态` 属性驱动样式，共五态（**优先级从上到下**）：

| 态 | 何时 | 表现（风格 B 的语汇） |
| --- | --- | --- |
| `剧终` | `已剧终` | 球外圈一圈**朱红细环**（静止） |
| `离线` | 引擎离线/熔断自动暂停 | 球变 `inkFaint` 灰、环虚线 |
| `出错` | 上次推进失败（未恢复） | **朱红环 + 常驻**，直到下次成功；hover 显示上次失败原因 |
| `编排中` | 引擎调用进行中 | 环**缓慢旋转/呼吸**（1.6s 循环）；hover 显示"正在编排本幕…" |
| `待命` | 其它（含冷启动记账、无指令） | 现状外观；hover 显示"最近：本幕节拍=X / N 分钟前" |

- 动效遵守 `prefers-reduced-motion`（那时用静态字符/边框变化代替旋转）。
- 球直径与层序**不变**（40×40）；只在球内画环，**不改 iframe 尺寸**。
- hover 文案用 `title` 或既有 tooltip 机制，**不新开弹层**。

## 4. 规格 B：提示条事件表（可配通道）

| 事件 | 类型 | 文案（示例） | 默认开？ |
| --- | --- | --- | --- |
| 开始推进 | info | `外部编剧正在编排本幕…（最近 2 条回复）` | ❌ **默认关**（球已经在转，避免噪音） |
| 推进完成 | success | `编排完成：本幕节拍 → 兑现伏笔 · 用时 48s` | ✅ |
| 冷启动记账 | success | `已记账（冷启动 第 2/3 轮 · 第 4 轮起下令）` | ✅ |
| 推进失败 | error | 现状（含连败计数与"面板可恢复"） | ✅ |
| 自动暂停/熔断 | warning | 现状 | ✅ |
| 编剧备忘未送达 | warning | 现状（E1 的可读原因） | ✅ |
| 楼层未落盘 | warning | 现状 | ✅ |
| 已剧终 / 群聊 / 无 AI 回复 | warning | 现状 | ✅ |

**新增设置项**：设置页 → 导演区 加 `提示条`（下拉，默认 **「完成与异常」**）：
`全部（含开始）` / **`完成与异常`** / `仅异常` / `关闭`。
（`关闭` 时**球状态仍然工作**——状态不依赖提示条。）

**"用时"从哪来**：`update.ts` 在开始与完成处各取一次 `Date.now()`，差值即用时；失败时也记入日志页。

## 5. 规格 C：面板内的可见性（辅助通道）

- **状态条**（已有四态）保持；`编排中` 期间状态条追加一个**细进度条**（不确定态，来回扫动），让面板开着的人也知道。
- **日志页**：保持 `captureConsole`，并给"开始/完成/失败"三类各加一行带时间戳的记录（现在开始那行已有，补上**用时**）。

---

## 6. 验收

1. **不用打开面板**，仅凭球就能判断：正在编排 / 空闲 / 出错（三种一眼可辨）；
2. 每轮默认**最多 1 条**提示条（完成或失败），设成「全部」才 2 条；
3. 提示条位置**不被面板遮挡**（现有锚点逻辑改好后，与球/面板同侧且留边距）；
4. 失败后球的"出错"态**持续到下次成功**，不需要打开面板确认；
5. 用例钉住：状态机优先级（剧终 > 离线 > 出错 > 编排中 > 待命）、提示条开关四档行为、"关闭"时状态仍工作、`prefers-reduced-motion` 下无旋转；
6. 门槛：`pnpm test` 全绿 + `tsc` 零错 + 平台直连 0 + 零截断（`.slice(` 0）。

---

## 7. 待确认（dsh 的判断，可推翻）

1. **开始提示默认关**——理由：球在转已经是"正在更新"的最强信号，每轮两条提示偏吵。用户若想要，设成「全部」。
2. **球的"出错"态保持到下次成功**——理由：错误提示条 8 秒后会消失，而"上次失败了"这件事应当**一直可见**，否则又得进面板看。
3. 不新增提示条"历史列表"（面板日志页已经是历史）——避免重复建设。
