- 验收：报告未写。

## 候选 5 真机复核（2026-10-01 收尾：只读复核 + 一次推进，最后清场）

- **事件编辑按 id 存住**：风闻页打开第一条事件（id=`emup35vwb8uzf`）改标题 → 保存，快照里**同一条 id** 的标题变成改后值 ✓
- **数组层不再产生重复项**：伏笔「复核·甲」第一次保存成功（2→3 条）；同名再存被拒绝，提示条原文「烟火「复核·甲」已经存在, 请换个名字」，快照仍是 3 条且该名字只有 1 条 ✓
- **势力只写改动**：潮汐城市政执委会把「动向」改成「复核改」保存后，快照里该势力 keys 仍是 {目标, 动向, 前情, 势力范围, 对外关系, 头面人物}，其余 5 键逐字与改前一致，提示条「已保存势力修改, 注入内容已同步」✓
- **清场**：清空（二次确认）后提示条「世界已归零: 快照清空, 世界书条目已删除, 之后只推进新楼层」，末条消息的 `烟火` 变量读到 null，面板回到「世界时间 未知 / 快照 无」✓
- 过程无与烟火相关的控制台报错

复核时记下的三个读法细节（以后写测试要注意）：

1. 提示条容器 `#yh-toast-stack` 在**顶层 document**，不在面板 iframe 里；成功类提示存活极短（约 1.4 秒后就读不到），要抓原文得在顶层挂 MutationObserver 或轮询。
2. 「推进世界」刚结束的瞬间，快照可能还落在**消息 0**，此时严格只读 `chat.length-1` 会瞬时读到"还没有快照"；稍等再看才落在最后一条消息上。
3. 风闻页事件的显示顺序与快照数组顺序不同（显示的第一条可能是快照里的第二条），所以判定要按 id，不要按位置。
