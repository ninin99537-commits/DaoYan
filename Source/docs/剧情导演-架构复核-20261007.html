一句话结论

剧情导演的分层是成立的：平台能力全部经 host.ts 单一接缝，慢 API 只在 update.ts 一条异步管线里跑，账本知识集中在 schema.ts + 字段表.ts。本轮复核真正的问题不在分层，而在三处「同一件事写了多遍」： 标签过滤在三插件各写一份、面板改账本后的副作用链手抄八处、更新管线里取料与编排糊在一起。 这三处本轮已收口（①②③），另补了 DaoYan 仓库缺失的类型声明（④）。 剩下最大的单点是视图层 悬浮球界面.vue（1464 行），属可控但不轻。

一、模块地图

按「谁能碰平台、谁能碰状态、谁只算数」分层，从下往上读。

1. 平台接缝层

模块行职责
host.ts225 全插件唯一直接命名酒馆助手全局的地方（getVariables / getChatMessages / injectPrompts / getWorldbook …）。 对外只暴露 useHost() 与一个可替换接缝，测试靠它脱开酒馆跑。

二、四条分层红线

① 平台只经 host.ts。 除 host.ts 外任何模块不得直接命名酒馆助手全局。这条可机检（已有用例）， 是「不装酒馆也能跑测试」的前提。
② 慢 API 只在一条管线里。 update.ts 是唯一 await 模型的地方；GENERATION_AFTER_COMMANDS 注入路径只读内存里已算好的指令，绝不在那里等接口。这条守的是生成不卡顿。
③ 视图只声明意图，副作用收口。 视图可以改账本字段，但「改完要做什么」（落盘 / 重写备忘 / 重注指令）必须走同一个接口， 不允许各按钮手抄调用序列。这条是本轮新增 账本变更.ts 的理由。
④ 字段知识唯一来源。 「什么是终态」「每层容量多少」「节拍有哪些」只在 schema.ts / 字段表.ts 定义一次。面板、提示词、引擎规则一律取用，不重写字面判断。

三、复核结论与候选

复核找出三类「同一件事写了多遍」，以及一处仓库自洽性缺口。五条候选与落地状态：

候选问题落法状态
① 楼层标签过滤（[xxx] 之类的剥离规则）在三个插件里各有一份实现， 改一处要改三处，且已经出现细微不一致。 收敛为 src/共用/楼层标签过滤.ts（createTextFilter），三插件共用。 已完成
② 面板上 8 个「修账本」动作各自手抄「saveData → sync编剧备忘 → renew本幕指令」调用序列，顺序/开关/暂停标志各写各的； 「什么是终态」也在面板与提示词里各写一遍字面判断。 新增 账本变更.ts（提交账本变更(账本, 设置, 副作用)）收口副作用链； 字段表.ts 导出 是终态（章回/伏笔/冲突/弧线），面板、提示词、 引擎规则、指标共用同一口径。新增 18 条断言的用例钉住开关与顺序。 已完成
③ updateDirector 里「取料」与「编排」糊在一段：读最近回复、清空层过滤、 标签过滤、拼正文、读世界书、组消息全内联，主流程难读也难单测。 取料整段移入 取料.ts（采集本轮输入），与彼方 收集本轮输入.ts 同户型；updateDirector 只管编排。 行为不变（force 仍绕过清空层、无回复仍按手动/自动分别提示）。 已完成
④ DaoYan 仓库 Source/tsconfig.json 的 include 里写着 "@types"，但仓库里没有这个目录——新克隆下来 tsc/IDE 解析不到 getVariables / getChatMessages / injectPrompts / getWorldbook 这些全局。 把工作区根部 32 个声明文件（function/ + iframe/）补进 Source/@types/。 已完成
⑤ 本轮复核结论此前只存在于对话里，没有可归档、可对照的文档。 本文件。 本次

未采纳 / 留待需要时

  • 把 update.ts 拆成可替换的 adapter（取料 / 应用 / 落盘）。 复核时列为候选，评估后只取了「取料」这一段（③）。再往下拆「应用 / 落盘」收益递减： 它们是纯变换 + 一次快照写入，边界已经清楚，拆出去只会多一层参数传递。
  • 把 悬浮球界面.vue（1464 行）按 tab 拆子组件。 这是当前最大的单体，但它是视图：拆与不拆不影响可测性（逻辑该在 .ts 里的都已在了）， 且拆动会牵动模板、样式、拖拽机制，回归面大。留待下次真要改界面结构时顺势做。
  • 快照.ts（474 行）再分家。 它同时管「楼层快照」「删楼回退」「离线熔断计数」三件事，命名已经比职责窄。 本轮没动，因为它的用例（删楼三场景）是全家最扎实的一块，动它要有明确理由。

分布本身说明问题所在：逻辑层没有胖子——最大的纯函数模块 360 行，且都是单一职责； 真正的大头是视图（1464）与它的机制（449）。这反过来说明分层是有效的： 复杂度堆在「界面」这一端，而没有渗进引擎与账本。

五、后续建议

  1. 保持红线可机检。「除 host.ts 外无平台直连」已有用例； 可再加一条同类的：「除 账本变更.ts 与 快照.ts 外， 视图不得直接调用 sync编剧备忘 / renew本幕指令」， 防止副作用链日后又被抄回去。
  2. 下次动界面结构时顺手拆 悬浮球界面.vue。 不要为拆而拆；按 tab 拆成子组件时，模板/样式/拖拽一起迁，一次做完。
  3. 新字段一律先落 schema.ts + 字段表.ts。 本轮 是终态 的教训是：只要允许「就地写一个字面判断」， 它就会在四个地方各长一遍。
